We used the trace for P10, which evaluates ancestor(X, jim), to observe how Prolog searches for answers. Activity 15 models execution using a runtime stack, where a frame is pushed when a function is called and removed when it returns. The same idea can be seen in the trace. For example, Call: ancestor(X,jim) pushes a frame, followed by Call: parent(X,jim), which pushes another. When parent(pat,jim) succeeds, Exit: ancestor(pat,jim) represents its frame being popped. The following Exit: ancestor(pat,jim) removes the ancestor frame. A Fail line also represents a goal ending unsuccesfully and its active frame being removed.

The first answer is X=pat, but Prolog does not immediately discard every possibility of finding another answer. After the first answer, the trace shows Redo: ancestor(pat,jim), followed by Redo: parent(pat,jim). Redo resumes a goal through a saved choice point. This preserves information about alternative clauses and the variable bindings needed to try them. In Activity 15, a returned frame has already been thrown away, so it cannot resume an earlier call in the same way. Prolog can instead backtrack to an earlier choice point and continue searching. This is why P10 produces three answers: pat, tom, and bob before the final Fail: ancestor(X,jim) shows that no more answers are available.

The order of the recursive clauses also affects how the search proceeds. In reach/2, the recursive clause calls reach(X,Z) before checking edge(Z,Y). The recursive call therefore happens without first moving to another node in the graph. If this clause comes first, Prolog keeps calling the same goal and may never reach the second clause, which checks an edge directly. In contrast, the recursive clause of ancestor/2 first checks parent(A,P) and only then calls ancestor(P,D). Each recursive call moves to another person in the family tree. Since the family relationships do not contain a cycle, this recursion can eventually reach the base clause.

Swapping the clauses of ancestor/2 therefore changes which answers appear first, but does not prevent the search from finding them. The difference is that ancestor/2 makes progress before recursing, while reach/2 recurses before making progress. The trace demonstrates how Prolog uses choice points to explore alternatives, while the clause order determines whihc paths it explores first.
